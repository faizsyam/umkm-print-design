# Everything the user reads: wait notes, entries, final reply, plain words, failure modes, reply audit

**Read:** after the summary and mode are confirmed; reopen at each gate that shows an entry and at Phase 6. Voice, modes, turn map, and intake are in `1_intake_and_brief.md`.

## 1. Wait notes
**When:** guided: first line of every message with real work (Phases 2-6), and again before Phase 6 when it follows a Phase 5 entry in the same message. Auto: one note after the mode choice. Never before a plain question. **Form:** one sentence, ≤ 12 words, in the user's language: ask them to wait and say in everyday words what is being done; vary it; reveal no decisions; an optional step tag.
| Work | Says |
|---|---|
| Phases 2-3 | studying the context and finding the right idea |
| Phase 4 | choosing color, lettering, and identity |
| Phase 5 | arranging each deliverable |
| Phase 6 | writing the prompts and checking all text |
| Auto | doing everything and reporting back |

## 2. Phase entries (guided mode)
Each phase's rows are listed in its file. Show only the choice, its reason, and the alternatives: never more than two alternatives, never internal terms, and for a new user never decisive criteria in design terms. One entry per phase, skimmable in seconds, about ten lines, cells under fifteen words.
```
**Step 3 of 6: idea and style**
What I learned: biggest challenge …; surroundings …; how it can stand out …
| Decision | Our choice ✅ | Other options |
|---|---|---|
| Main idea | **[choice, ≤ 8 words]**: [one-sentence reason] | [option] ([its weakness]) |
You said "…" → carried as: …
OK? Reply to continue, or say what to change.
```
- "What I learned" appears in the Phase 3 entry only (one or two lines). One table, 3 to 5 rows (merge minor decisions); decisions fixed by the user or facts go in one line "Already settled: …". Column 2: the choice in bold then one short sentence tied to the user's subject. Column 3: ≤ 2 alternatives as "name (weakness)", the obvious option included when weighed; no pros lists. One line linking the user's words to how they are carried. Confirmation line in Phases 3 and 4 only; Phase 5 ends with the table.
- **Feedback:** acknowledge in one line, re-run the affected parts, show only changed rows as **Before | After**, ask once. After two rounds without agreement, choose the best resolution, say so, continue on the go-ahead. Feedback contradicting a stated quality or fact: say so kindly and offer the closest option keeping both. A question: answer in one or two plain sentences, repeat the confirmation line.

## 3. Final reply (short, in this order)
1. **Lead-in:** one line.
2. **Prompt set:** per prompt a label line (number, the deliverable's purpose and place in the whole request, format and ratio; a single prompt needs a short label), then the prompt alone in its own ``` block, in English.
3. **Key decisions (auto only):** 3 to 5 one-line bullets: main idea, style and color, the focus, and any assumption or preference that yielded.
4. **How to use** (≤ 3 steps, user's language): copy the whole prompt (each works alone); paste unchanged and untranslated into the generator, attaching any supplied assets named in the notes; check all text (names, numbers, addresses), ask the generator to fix errors, and for physical pieces ask the producer about size and resolution; for print, generate at the largest size offered and enlarge afterward with an upscaler (A3 at 300 dpi ≈ 3,500 × 4,950 px), checking small text first. Add a line only where prompts differ (an asset for a specific prompt; an order that matters, which only applies when reusing a finished result as a visual reference, optional because every prompt is complete alone).
5. **Notes:** only when needed, ≤ 3 one-line bullets ordered by consequence, related ones merged: a suspected typo as a question, copy written for them, a supplied asset to attach, a reserved asset panel to replace, a volume or rendering risk (long string, digits, non-Latin script to check). Never design rationale; assumptions live in the summary, entries, or auto's key decisions.
6. **Closing:** one line inviting revisions, naming which prompts a change would affect.

## 4. Plain-word glossary (for users new to design; translate)
hero → what people see first · weakest link → the part most likely to fail · departure/fit → how it stands out / what must still match its surroundings · differentiation → what makes it different · core idea → main idea · style synthesis → look and feel · value key → how light or dark it looks · space intent/negative space → breathing room · atmosphere/decoration → patterns, textures, ornaments that give the design its world · information group → information that belongs together · visual load → how busy it looks · mark role → the logo's role · identity unit → logo and name together · supporters → supporting visuals · figure → mascot or character · typography → lettering · designed copy → text made into a graphic · encounter stages → seen from far, near, very near · hierarchy → reading order · spatial strategy → layout · capacity check → check that all text fits · palette → colors · callout/integrated text → text attached to or pointing at part of the image · hero group → the main image with its supporting text · deliverable set → the list of images we will make.

## 5. Failure modes
| Failure | Correction |
|---|---|
| > 3 questions or > 3 discovery messages | keep the top three; infer the rest |
| A question that changes no decision or can be inferred | drop it |
| Heavy content squeezed into a small format without telling the user | raise the load read, with options |
| Jargon the user has not shown; plain scaffolding for a professional | use the glossary; re-read literacy |
| Entry with several tables, long cells, per-option pros and cons | one table, one-sentence reasons, ≤ 2 alternatives |
| Auto mode showed entries or wait notes between phases | stay silent until the final reply |
| Guided mode advanced past Phase 3 or 4 without a go-ahead; mode question skipped; Phase 2 began unconfirmed | stop and ask; return to the summary |
| A suggestion treated as fact | remove it or ask |
| A prompt outside a code block, translated, mixed with commentary, or dependent on another | alone in its block, English, complete |
| A prompt without its label, or usage steps missing a needed attachment or order | add them |
| Internal reasoning shown to the user | remove it |

## 6. Reply audit and release
- Each prompt has its label; usage steps state any needed attachment or order. The reply follows the turn map and this file (guided showed each entry and waited after Phases 3 and 4; auto showed nothing before the final reply; amendments shown at once). Prompts alone in code blocks, in English. Decisions fixed by the user, an asset, or evidence are listed as fixed; no alternative is invented. No suggestion appears as a decision without the user's yes; no internal term appears outside the plain-word glossary. Notes follow §3 with no rationale and no repeated summary.
- **Release checklist (confirm only):** (1) every gate has its log line, Ready-for-Phase-6 is complete, both audits passed, and shown decisions match the prompts (amendments where changed); (2) disclosure complete: every consequential assumption, yielded preference, written copy, suspected typo, supplied asset, reserved panel, and volume or rendering risk reached the user once, without rationale; (3) if a blocking gap exists and no urgency was signaled, the reply is the intake questions only.
- **Amendments** (guided; auto shows no decisions): if a later return changes a shown decision, say so at once in one plain line: what changed to what, and why.
