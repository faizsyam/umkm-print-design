# Gates, assembled review, triage, and revisions

**Read:** at the Phase 5 gate; on any failed check, test, or audit; on a revision request.

## 1. Hand-off check (end of every phase)
Run these, then the phase file's own gate.
1. Every required decision is made by its class (Direction shows its record at the openness in S; System shows its comparison or derivation; Execution items are not logged).
2. Every decision names its source and was made after its inputs existed (a decision resting on a later phase's output is provisional, tagged). Each stated quality has a visible carrier at this phase's level (plan, system, composed glance stage) and no decision signals its opposite.
3. This phase's decisions agree with those it reads; a conflict returns to the earliest conflicting decision.
4. User-facing: Phase 1 closes only on the confirmed summary and mode. Guided: wait note on each message with real work; entries for Phases 3-5 at their gates in the user's language; stop for confirmation after Phases 3 and 4. Auto: one wait note, nothing at gates. Phase 6 is the final reply.
5. D, obligations, and flags are appended to the Design Log. A pass is one line; failures and fixes are written out.
6. **Failure route:** return as below, carry back what it lists, set dependents stale, re-run forward, count against the issue's two-cycle cap.

| Gate | Return to | Carry back |
|---|---|---|
| 1 | the Phase 1 step the failed check names; a user-facing failure returns to intake | the failed check; ledger rows concerned |
| 2 | the Phase 2 step that produced the failed artifact (research, profile, differentiation/inventory, problem, implications) | check; finding or implication |
| 3 | the failed decision's card (criteria, survey, idea, style, hero, principles); a failed direction check goes to the earliest decision it implicates (idea, style, hero, principles) | check; decisions implicated; tension or obligation |
| 4 | the Phase 4 file owning the failed part, or Phase 3 principles if the plan caused it | check; the part, its purpose line, the commitment it realizes |
| 5 | the earliest responsible step: stages and map, needs/composition/space plan (`8`), placement, load, balance, capacity, review (`9`); Phase 4 if the system is the cause | check; deliverable; decisions; frozen sizes are discarded when the return precedes the capacity check |
| 6 | the earliest cause: a clause, the prompt set or structure, or the owning earlier phase when a needed decision does not exist | failed audit item; the sentence; the Specification field |

## 2. Assembled review (once, at the Phase 5 gate)
Run on the assembled design with the composition review (`9_place_and_check.md` F). Phase 3 runs only its direction check. Each test runs once; afterward only tests a changed decision touches re-run. Load and fit ran in `9_place_and_check.md` C and re-run only if a later decision changed an extent or addition.

| Test | Question | Routes to |
|---|---|---|
| Contradiction scan | Do brand design, theme, idea, style, hero, system, mark, composition agree, and do hierarchy, sequence, placement agree? Across a set: shared decisions identical, differences explained by format or encounter? | the earliest conflicting phase |
| Brief-quality | Does each stated quality have a visible carrier in the composed glance stage, and does any decision signal its opposite? | Phase 1 for the translation, else the earliest contradicting phase |
| Decided-attribute | Is any look-shaping attribute left to the model's apparent value? | the phase that should own it |
| Originality | The protocol's three tests: predictable, specific, ambitious | the deciding phase |

**One objection:** the strongest case against the riskiest decision (highest consequence on thinnest evidence, or a compounding accepted cost), raised by the owning role, then resolved or accepted with a recorded reason; it must add something the protocol's challenge did not. **An objection naming a legibility, floor, or mandatory-content failure is resolved by a change on the ladder, never accepted;** acceptance is for risks of taste and originality. A defect is traced to the earliest responsible decision.

## 3. Ready for Phase 6 (completeness of the Design Log at the Phase 5 gate)
Each commitment must exist as a drawable, prompt-ready specification; reasons were verified at their own hand-offs and are not re-argued or passed on. A missing or vague item returns to its owner; a reason naming no observable property fails.

| Commitment | Must exist as |
|---|---|
| Deliverable set | per deliverable its format and ratio from S, stated in its prompt, never substituted; prompt count equals the set |
| Message | one sentence, confirmed in Phase 5 |
| Each quality | its carriers and the resulting value key as visible features |
| Each content item | role, grade, stage, group, placement, per deliverable |
| Supporters and decoration | per addition: purpose line, form, region, weight ceiling; or the reason the piece stays plain; atmosphere vocabulary and location, or the decision it holds none |
| Figure | origin, roles, the one shared design |
| Context | what the design shares with surroundings and the dimension it departs on, as visible traits; the distinguishing traits vs peers |
| Core idea, style, hero | drawable terms: true specifics depicted, image-making language, the hero's reinforcing content or reason to stand alone, treatment vocabulary |
| Identifier | a fixed asset, or a new mark: device, geometry, integration logic, distinction mechanisms, forms and where |
| Shape language, balance | each container's function, form, fill; balance type and counterweight |
| Space plan | region table complete (shares, rank, mass class, side, clearance; each supporter's host and count); budget rows and free ground account for the whole format with headroom; quiet and atmosphere by what they separate or frame; reading route; arrangement form per group; quantity of every repeated form; planned wrap of every multi-line string; placement and role of every mandatory item |
| Obligations | each realized by a named decision or recorded as an accepted cost |

## 4. Triage and routing
| Severity | Definition | Action |
|---|---|---|
| Critical | violates a non-negotiable; mandatory content missing or altered; fixed asset altered; invented fact; a required decision never made | stop; return to the responsible phase; re-run forward; release blocked |
| Major | fails a gate check, test, or audit; generic, context-blind, or filled; mark absorbed by type | return to the earliest responsible decision; re-run forward |
| Minor | weak phrasing, a redundant clause, a small imbalance | fix in place without altering earlier decisions |

**Symptoms → responsible phase** (when several causes are possible choose the earliest; fixing a symptom later while its cause stands is a patch and not permitted).
- **1:** wrong, missing, altered content; unsourced fact; a quality missing; a deliverable or format missing, wrong, needlessly split; heavy load absorbed silently.
- **2:** unsupported narrative; environment-blind profile; a medium convention applied by default; weak inventory; groups missing, templated, or from the user's list order.
- **3:** generic idea, style, or hero (image-making language that is only a medium name); a hero left standalone with no reason; no space budget, a budget of ranges that does not sum or sizes the hero before the groups, a hero footprint above its row, a hero whose host cannot hold its text by geometry; density or vocabulary unstated; no decoration stance or undecided plainness; tension unresolved.
- **4** (3 if the plan caused it): containers all in the default form, or one design across roles/ranks (3 if no corner/edge geometry was set); an element or container with no purpose line; weak or styled-name mark; clashing color/type; value-key drift; ranked text left as scaled plain type; roles differing only by size; plain-set voice copy; an item Phase 5 promoted to rank 1-2 with no treatment decision; indistinguishable type roles; blank or category-generic piece (3 if no carriers planned); text-only look; uniform ground without reason; unrealized theme world with no decision; supporters without an information job or generic or repeating adjacent words; a style or figure named by category that fails the specificity test; a lead figure defined in one pass; decoration with no deficit, duplicate purposes, outranking information; counts above the density caps; a second identifier, unwanted or inconsistent figure, invented level mark; costs over the allowance or load beyond density; containers where spacing would serve; a counterweight added as new when one existed; decorated ground counted as quiet; treatments outside the vocabulary; a device costing the name's legibility; a name, copy treatment, or container arrangement fixed in line counts before Phase 5; a mark candidate contradicting the hero's form.
- **5:** hierarchy (competing elements, unclear first read, an effect not registering, a zone or text mass outranking its rank, a container lifting a secondary element, a sequence contradicting placement); scale and space (close text at the glance ratio; floors without engagement or render scale; reference text borrowing the lead's size; roles above floor with no rank reason; padding or margins as adjectives or below steps; headroom existing only by cutting spacing or quiet; every tier enlarged in a large format; crowding; a zone crowded at its own scale; load beyond the plan; quiet as slivers, decorated, or parked in one band; an element sized by its own wish; regions fixed before needs; pre-partitioned zones; free ground as leftover; quiet narrowed before earlier rungs; a fit failure worked by trial layouts instead of ledger and ladder); floors and units (glance floor on a whole name; core content at the deliberate floor; physical units; balance by coordinates; a legibility objection accepted; the same host and text retried instead of geometry and ladder); composition (overlap hiding an essential part, unlinked elements, lopsided mass, wrong stage, mark absorbed, a layout derived from another's, near-touch with no decided gap, a locked strategy the content cannot fill); text fit (overflow, late size changes, letters compressed/stretched/slanted, equivalent items typeset by length); grouping (picture-with-captions, field of labels, one row or container per supplementary item, a hero isolated from its support, parallel claims merged, one arrangement repeated across different functions, a long list as one column without reason, equivalent rows varying with content); edges (bleed against content, a pointer without a referent, a figure covering information).
- **6:** rationale in the prompt; vague wording; mandatory text misplaced; container height beside text sizes and counts that leave less than the padding; padding only "generous"; a look clause that fails the strike test; space, proportions, ground, or repeated-form quantities unstated; an ordering word contradicting a position word; partition words where no such form exists; atmosphere not stated apart from quiet; a prompt depending on another, omitting shared identity, or lacking its label.
- A stated quality contradicted → the earliest contradicting phase. An obligation realized by nothing → the phase that should have realized it.
**Routing rules:** cap each issue at two revision cycles, then take the best resolution and record it (a recurring issue has an upstream cause); a returned phase keeps unaffected decisions; after any change re-run the contradiction scan and touched checks and confirm no text still states the old decision.

## 5. Revision requests
| Change | Re-enter at | Stale |
|---|---|---|
| content, deliverables, format, ratio | Phase 1 | S and every later item that reads it |
| audience, setting, medium, reading conditions | Phase 2 | Phases 3-6 items reading profile, encounter, message |
| concept, mood, style, hero, mark role, space intent, density | Phase 3 | Phase 4-6 items reading the changed decision |
| color, value key, type, copy treatment, mark, lockup, supporters, containers, ground | Phase 4 | Execution Specification items naming the element; Phase 6 prompts carrying it |
| arrangement or emphasis | Phase 5 | the deliverable's Specification and prompt |
| wording only | Phase 6 | the affected prompts |
A request spanning rows re-enters at the earliest; one fitting no row is traced with the symptom list. Set stale flags first; unaffected decisions stay settled. Read S and D (Basis/Rejected only where the return rule needs them) and the batches of re-entered phases if not in context. Redo in order the decisions that read the changed one; tell the user briefly what is redone and show only what changed as a Before | After table in their language. Re-run only touched checks plus the contradiction scan and any quality whose carrier changed; the prompt audit always runs in full on every fresh prompt. Feedback at any confirmation takes the same route. Deliver a fresh complete prompt for each deliverable whose content changed and name those that did not.
